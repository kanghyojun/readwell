# AI로 긴 글 잘 읽기: 방법론과 구현

긴 글을 AI를 활용해 빠르고 정확하게 읽는 방법, 그리고 그걸 실제로 돌릴 도구를 어떻게 만들지 정리한 문서다.

---

## 1. 읽기 방법론

### 전제: 요약은 별로다

요약은 **AI가 무엇을 버릴지 대신 결정**해버린다. 정작 알고 싶던 디테일이나 저자가 공들인 논증의 연결고리가 사라진다. 결과물만 보면 다 안 것 같은데 실제로는 원문을 못 읽은 상태가 된다. 실무자들도 같은 얘기를 한다. "대부분의 AI 요약은 빠르지만 아이디어를 평면화한다(flatten ideas)."

그래서 방향은 하나다. **AI의 역할을 "압축기"에서 "안내자 / 검증자"로 바꾼다.** 원문은 그대로 두고, AI가 내 읽기를 빠르게 만들거나 내 이해를 검증하게 시킨다. 요약을 없애는 게 아니라, 원문으로 돌아가는 **색인**으로 격하시킨다.

### 방법들

| 방법 | 무엇을 하는가 | 언제 좋은가 |
|---|---|---|
| 질문 기반 추출 | 내 질문의 답을 **원문 문장 그대로 인용 + 위치**로 받는다 (요약 금지) | 거의 모든 글. 평면화를 막는 가장 확실한 장치 |
| 3-Pass 읽기 | 스캔 → 핵심 주장 → 세부, 줌 레벨을 단계로 분리 | 기술 문서, 논문 |
| 요지 색인 (gist) | 섹션별 한 줄 요지 + 위치만 뽑아 원문 회귀용 지도로 | 길고 구조 복잡한 글 |
| 주장-근거 매핑 | 핵심 주장과 그 근거, 근거 위치를 표로 | 논문, 설득형 글 |
| 대화형 정독 | AI를 토론 상대로 단락별로 같이 읽기 | 낯선 분야, 기억에 남기고 싶을 때 |
| 비판적 읽기 | 숨은 전제, 약한 근거, 빠진 반례를 짚게 | 주장글, 검증이 필요한 글 |
| Feynman 검증 | 내가 먼저 요점을 말하고 AI가 빈틈을 짚음 | 체화. 외주화 함정 회피 |
| 개념 글로싱 | 막히는 용어·배경지식만 그때그때 풀어줌 | 낯선 분야 원문 정독 |

### 참고한 외부 인사이트

- **ReadAgent (Google)**: 글을 단위로 나눠 짧은 요지 메모(gist memory)를 만들고, 질문이 생기면 그 메모를 색인 삼아 **해당 원문으로 되돌아가 다시 읽는다.** 요지가 결론이 아니라 길찾기용 지도라는 점이 핵심.
- **원문 옆 도구**: alphaXiv, Lumi, Papiers 같은 도구의 공통점은 원문을 치우지 않는다는 것. "원본 읽기 경험을 대체하지 않는 도구를 골라라."
- **체화 (MIT 연구)**: AI 요약본만 쓴 사람의 80%가 자기가 쓴 내용을 정확히 인용하지 못했고 뇌 영역 간 연결성도 약해졌다. 정독·메모·스스로 하는 요약이 빠지면 머리에 남지 않는다.

### 실전 순서

1. **지형 파악**: 구조 지도 / 3-Pass 1단계로 전체 윤곽
2. **관심 구간 특정**: 질문 기반 추출로 어디를 직접 읽을지 고름
3. **직접 정독**: 그 구간만 읽고, 막히면 글로싱
4. **체화**: Feynman 검증으로 내 이해 점검
5. **검증**: 비판적 읽기로 마무리

이러면 AI가 글을 대신 읽어주는 게 아니라, 내가 읽되 길을 안내받는 형태가 된다. 빠르면서 원문 접촉이 유지된다.

### 바로 쓰는 프롬프트

질문 기반 추출:
> "이 글에서 다음 질문들의 답을 찾아줘. 단, 네 말로 요약하지 말고 답이 담긴 원문 문장을 그대로 인용하고 위치(섹션/문단)를 알려줘. 답이 없으면 '없음'이라고 해. 질문: …"

3-Pass:
> "이 글을 3단계로 안내해줘. 1단계는 전체가 무엇에 관한 글인지 한 문단 스캔, 2단계는 핵심 주장과 그게 왜 중요한지, 3단계는 내가 '깊게'라고 말하는 섹션만 세부까지. 지금은 1단계만 해줘."

요지 색인 (원문 회귀용):
> "내용을 압축하지 말고 각 섹션의 한 줄 요지와 위치를 표로 만들어줘. 요지를 풀어 설명하지는 말고, 내가 어디로 돌아가 직접 읽을지 고르는 지도로만 써줄 거야."

비판적 읽기:
> "이 글의 핵심 주장마다 (1) 깔고 있는 숨은 전제, (2) 근거가 약한 지점, (3) 저자가 다루지 않은 반례를 짚어줘."

Feynman 검증:
> "이 섹션에 대한 내 이해를 적을게: [내 메모]. 내가 틀리게 이해한 부분, 빠뜨린 핵심, 근거 없이 단정한 부분만 짚어줘. 새 정보를 길게 덧붙이지는 말고."

### 글 종류별 무게중심

- 기술 문서 / 매뉴얼: **구조 지도 + 질문 추출**이 압도적으로 유용
- 논문 / 주장글: **주장-근거 매핑 + 비판적 읽기**가 더 값짐

## 2. 구현 방법

### 구독으로 돌리는 두 갈래

핵심 구분: "Claude **구독**(Pro/Max)"으로 되는 건 Anthropic 공식 경로뿐이다. 서드파티 확장(Sider, Monica 등)은 대부분 Claude **API 키**(종량제)를 요구하므로 "이미 내는 구독료로" 목적과 안 맞는다.

| 경로 | 구독으로 되나 | 비고 |
|---|---|---|
| **Claude in Chrome** (공식 확장) | 된다 | 모든 유료 플랜 베타. Chrome 전용. Pro는 Haiku만, Max는 Sonnet/Opus 선택 |
| **Claude Agent SDK** (Claude Code 기반) | 된다 | `ant auth login` / `claude` 로그인의 구독 OAuth를 그대로 물려받음. 개인 로컬 도구용 |
| `anthropic` API SDK | 아니다 | 종량제 API 키. 쓴 만큼 과금 |
| 서드파티 확장 + BYOK | 아니다 | API 키 종량제. 비추천 |

Agent SDK가 구독으로 도는 게 이 구현의 전제다. 단 개인용으로만 쓴다. 프로그램으로 대량 호출하면 구독 사용량 한도에 걸리고, 외부 다수에게 서비스하는 건 약관 위반이다.

### 추천 아키텍처: 로컬 파이프라인

```
URL
 → 본문 마크다운 추출 (Jina Reader 또는 trafilatura)
 → Claude Agent SDK (구독 인증)로 방법론 실행
    (3-Pass → 요지 색인 → 질문 추출 → 비판적 읽기)
 → 결과를 Obsidian vault에 .md로 저장
```

CLI 한 줄(`read-it <url>`)로 만들면 URL만 던지면 깨끗한 본문을 받아 방법론대로 돌리고 결과를 파일로 남긴다. 북마클릿으로 현재 탭 URL을 로컬 서비스에 POST하면 "확장 비슷한 편의 + 로컬 파이프라인"을 둘 다 가진다.

### 마크다운 추출 도구

| 도구 | 방식 | 비용 |
|---|---|---|
| **Jina Reader** | `https://r.jina.ai/<URL>` 프리픽스 한 줄. JS 렌더링 처리 | 키 없이 무료(속도 제한). 키 발급 시 1천만 토큰 무료. 유료 $20/월~ |
| **Firecrawl** | `/scrape` API로 URL → 마크다운. 크롤링까지 | API 키 필요(무료 티어 있음) |
| **trafilatura** | Python 라이브러리로 로컬 본문 추출 | 완전 무료, 외부 의존 없음 |
| Readability / MarkItDown | HTML → 마크다운 변환 라이브러리 | 무료 |
| Obsidian Web Clipper | 보고 있는 페이지를 바로 옵시디언으로 | 무료 |

정적인 블로그가 대부분이면 **trafilatura**로 충분하고 외부 호출도 없다. JS로 렌더링되는 페이지가 많으면 **Jina**가 더 잘 가져온다. 블로그 몇 개 읽는 용도면 Jina 무료(키 없이)로 충분하다.

### 비용 정리

- **Jina**: 키 없이 무료(IP 기준 속도 제한). 키 발급 시 신규 1천만 토큰. 배치로 수백 개씩 안 긁으면 돈 낼 일 없음
- **Agent SDK**: 구독 사용량 한도 내에서 동작. 추가 과금 없음
- **trafilatura**: 무료

### 로컬 서비스 vs 확장, 어느 쪽?

**로컬 서비스가 나은 경우**
- 내 읽기 방법론을 코드로 고정해 반복 실행
- 결과를 옵시디언/파일로 자동 저장 (체화 메모와 연결)
- 공개 블로그가 대상 (Jina로 fetch 쉬움)
- 여러 글 배치 처리

**확장(Claude in Chrome)이 나은 경우**
- 로그인 / 페이월 뒤 콘텐츠 (Jina가 못 가져옴)
- "지금 보는 페이지" 즉석 질문
- 만들기 싫고 바로 쓰고 싶을 때

"공개 블로그를 내 방식으로 반복해 읽고 결과를 노트에 쌓고 싶다"면 로컬 서비스가 맞다.

### 환경 주의

현재 작업 머신은 GUI 없는 headless SSH 환경이라 브라우저 확장(Claude in Chrome)은 못 띄운다. Jina 호출·Agent SDK·파일 저장은 다 잘 돌지만, 확장은 데스크톱(Mac 등) 몫이다.
